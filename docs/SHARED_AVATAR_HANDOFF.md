## SCOOP RUSH — เพิ่มหมีมุมบนจริง

งานต่อจากคำขอแก้หมีด้านข้าง อัปเดตบรันช์เดิมด้วย `main` ที่รวมชุดงานก่อนหน้าแล้ว (`9295057dbbcc6fa502fcaad1ad4cf368dc4b01d7`, PR #264) จากนั้นแก้เฉพาะ renderer หมี/ผู้ขี่และเอกสารนี้ ไม่มีการรันทดสอบหรือเปิดเกมในรอบแก้หมี

- หมีหัน −Y ในพิกัด local มีหลังและสะโพกทรงยาว ขนขาวไล่เงาฟ้า หางด้านท้าย หูกลมสองข้าง และจมูกดำที่ปลายปากด้านหน้า ไม่ใช้ลำตัวด้านข้างหรือการ mirror ซ้าย–ขวา
- อุ้งเท้าหน้าซ้าย/หลังขวาก้าวพร้อมกัน อีกคู่ก้าวสวนกัน ระยะขยับ ±1.6 world units; เส้นนิ้วอยู่บนหลังเท้า ไม่มีฝ่าเท้าหันขึ้นหากล้อง
- `Art.drawBear(ctx,color,stride)` วาดอุปกรณ์ในพิกัด local เท่านั้น ผู้เรียกย้าย Canvas มาที่ `(p.x,p.y)` แล้วหมุนตาม `PartyPlayerAvatar.heading(p)` ก่อนวาดทั้งหมีและผู้ขี่
- `Art.BEAR_MOUNT` เป็นแหล่งพิกัดอานเดียวกันสำหรับภาพอานและผู้ขี่: `seatY:6`, `riderScale:.8` ผู้ขี่ใช้ `local:true`, `heading:0`, `holding:true`, `attacking:false`, `combat:false`, `label:false`, `shadow:false` จึงหันตามหมีครั้งเดียว และรับเครื่องแต่งกายจากตัวกลาง
- ลำดับซ้อนภาพของผู้ขี่หมีอิงจุดพื้น `p.y` เงาอยู่ใต้หลังหมี ไม่ใช่เส้นเงาใต้เท้าแบบด้านข้าง การขยับเท้าไม่ย้ายอานหรือแก้ state ฟิสิกส์

**ฝาก AI ผู้ทดสอบ:** ตรวจหมีและเครื่องแต่งกายครบแปดทิศ ทั้งยืน/เดิน/หยุด/ดันไอศกรีม ขอบลานและการซ้อนภาพ ใน tier 1–6 และ 7–12 คน ตรวจว่าผู้ขี่นั่งบนหลังไม่ไหลออกด้านข้าง หมวกใช้ anchor เดียวกับตัวกลาง และหัวหมีไม่ถูกตีความเป็นหน้า/หมวกอีกชั้นของผู้เล่น จากนั้นทดสอบและรวมตาม workflow เดิม หลักฐาน QA ของ PR #264 ไม่ครอบคลุมรูปหมีใหม่นี้

## สัญญาของตัวละครกลาง

- เรียก `draw(ctx,p,options)` ด้วยข้อมูลผู้เล่นครบ ห้ามสร้างผู้ขับใหม่ด้วยเพียง `{color,x,y}` และห้าม bake หัวหรือหมวกลงใน cache ของพาหนะ
- เพิ่ม `options.heading` เป็นมุม **radians ใน Canvas ปัจจุบัน**: `0` = หน้า −Y, `Math.PI/2` = หน้า +X ถ้าไม่กำหนด ใช้ทิศเดิมของผู้เล่น/หมัดตามเดิม ตัวเลือกนี้ทำให้เบาะที่หมุน Canvas ไว้แล้วไม่หมุนผู้ขับซ้ำตาม `p.dir`
- เพิ่ม `options.shadow:false` เพื่อให้พาหนะเป็นเจ้าของเงาบนพื้น ค่าเริ่มต้นยังวาดเงาตัวละครเหมือนเดิม
- ผู้ขับใหม่ใช้ `local:true`, `holding:true`, `attacking:false`, `combat:false`, `label:false` และ `shadow:false` ให้ภาพอยู่ที่เบาะและไม่รับท่าต่อยค้างจากรอบอื่น UFO ไม่กำหนด `heading` เพราะห้องขับไม่ได้หมุน Canvas จึงใช้ `p.dir` ตามปกติ
- วาดหมวกใน transform เดียวกับหัวของตัวกลาง รวม scale/heading/alpha ที่รับมา พาหนะวาดก่อนผู้เล่น ไม่สร้าง clip ตามขนาดห้องขับ ไม่ชดเชยมุมหมวกซ้ำในแต่ละเกม
- ขนาด SVG ตัวกลางยังเป็น 52 world units ก่อนคูณ scale ของผู้เรียก; การเปลี่ยนพิกัดอานเป็นการวาดเท่านั้น ไม่แก้ `p.x`, `p.y`, `p.dir`, hitbox, ระยะใบมีด, คะแนน, เวลา, bot, ความเร็ว, world tiers หรือ DPR

## งานหมวกที่ยังต้องเชื่อม

การย้ายแมพมาใช้ตัวกลาง **ไม่ได้เปิดระบบหมวกที่รอรวมอยู่เอง** ตอนนี้ `player-avatar.js` ยังไม่ได้โหลด overlay ของชุดหมวก หรือเปิด B ในเขตเสื้อผ้า อ่าน [งานส่งต่อเครื่องแต่งกาย](../assets/cosmetics/HANDOFF.md) และ `wardrobe-assets.json` ต่อเพื่อเชื่อมทั้ง 7 ชุดกับ `none`, palette, portrait/overhead/punch/Canvas fallback และ identity/room/reconnect รวมถึง state ที่ Plaza ส่งเข้า renderer

เมื่อเชื่อมแล้ว ให้ใช้ทางวาดกลางข้างต้นโดยไม่เพิ่ม renderer หมวกแยกในรถ/เลื่อน/เครื่องตัดหญ้า/UFO/ผีผู้เล่น การเลือกชุดในรอบใหม่และการแสดงผู้เล่นเดิมควรได้ข้อมูลผ่าน `p` ตามเดิม

## ส่งต่อ AI ที่รับผิดชอบการทดสอบและรวม

รายการนี้เป็น **งานที่ยังไม่ทำ** ไม่ใช่ผล QA:

1. อ่าน `AGENTS.md`, `CI_TESTING.md`, `MAP_SCALE_RULES.md` และกฎ connection; เชื่อมเครื่องแต่งกายก่อนตรวจภาพหมวกจริงทุกแมพ ทั้ง Normal Party และรอบมินิเกมใน Board Party
2. ตรวจ player identity/cosmetic จากห้องและ Plaza จนถึง shared renderer ข้ามเกม เปลี่ยนสีและ reconnect รวมทุกชุด ทุกทิศ และท่าต่อย ตรวจสีเฉพาะส่วนตามข้อกำหนด SVG เดิม
3. ตรวจภาพและ Canvas fallback ของผู้ขับให้ใช้ตำแหน่ง/scale เดียวกัน ไม่เกิดหัวสองอัน ไม่ถูกโดม/หมวกประจำแมพบัง โดยเฉพาะเลื่อนขณะตกและเกิดใหม่, UFO ลอย/กระพริบ, ผีผู้เล่นในสองธีม และ NPC ที่ต้องยังแยกจากผู้เล่น
4. ตรวจ geometry, clipping, ความอ่านง่าย และมือถือ/iPad ตาม [ขนาดจากโค้ด](MAP_SCALE_AUDIT.md#shared-avatar-mounts-2026-11-12) ทั้ง 1–12 คนและทุกขอบ tier โดยเฉพาะ ICE RACE ที่แบ่ง 1–4 / 5–8 / 9–12 คน ไม่ใช่ 6→7 อย่างเดียว
5. รัน syntax และ preflight ที่เกี่ยวข้อง จากนั้นเปิด PR ให้ระบบเลือก QA ตามผลกระทบของ shared renderer และรอ required checks บน head ล่าสุดครบก่อนรวม การเปลี่ยน shared file ต้องใช้ขอบเขตตาม CI policy ห้ามถือว่าเป็น art-only เพื่อข้าม checks

ชุดตรวจที่เกี่ยวข้องมี `avatar-topdown.cjs`, `map-scale-regression.cjs`, `lawn-mower.cjs`, `color-claim.cjs`, `ice-race.cjs`, `ufo-arena.cjs`, `new-games-balance.cjs`, `minigame-balance.cjs`, `ghost-courtyards.cjs`, `smoke.cjs` และ browser suites ตาม registry ของ CI; ให้เพิ่มหลักฐานของ driver identity/ทิศ/ภาพ fallback ในงานของ AI ผู้ทดสอบ ไม่ได้เพิ่มหรือรันชุดทดสอบในรอบนี้
