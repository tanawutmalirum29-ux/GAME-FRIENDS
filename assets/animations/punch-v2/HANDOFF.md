# GAME FRIENDS — SVG หมัดสำหรับ AI ตัวถัดไป

**สถานะ: ออกแบบ SVG เสร็จ / ยังไม่เชื่อมเข้ารันไทม์ / ยังไม่ทดสอบ / ยังไม่รวม main**

คำสั่งผู้ใช้สำหรับรอบออกแบบนี้: ทำเฉพาะ SVG ให้ดี วางท่าทีละเฟรม ส่งตัวอย่าง และให้ AI ตัวถัดไปทดสอบแล้วรวม ห้าม QA หรือทดสอบใด ๆ ในรอบนี้ จึงไม่มีการรันเกม, syntax check, test, browser, build หรือ CI และไม่มีการแก้ไฟล์เกมเดิม

ต้นแบบ: `player-avatar.js` และ `combat-motion.js` จาก main commit `e1c536069ee856b0e7f7d5d1abc75818160c76c4` สาขาส่งงาน `art/punch-svg-frame-pack`

## หลักการภาพ

เป็นมุมมอง overhead ของตัวละครเดิม ไม่ใส่ขา ลำตัวตั้งตรง หน้ากากใหม่ หรือเครื่องแต่งกายเพิ่ม ดวงตาขาวยังอยู่ขอบด้านหน้า ศีรษะขยับและหมุนเล็กน้อย ส่วนไหล่หมุนมากกว่า จึงเห็นการง้างและส่งแรง

แขนขวาออกจากไหล่ขวา ผ่านศอกและข้อมือด้านข้างศีรษะ ไม่เริ่มที่ใบหน้าหรือ physics origin ใช้ท่อนแขนสองท่อน (15 และ 18 หน่วย SVG) พร้อมกำปั้นที่มีสันนิ้ว นิ้วโป้งและข้อมือ ความยาวกระดูกช่วงเคลื่อนไหวคงที่; ศอกพับ/คลายตามตำแหน่งข้อมือ ไม่ยืดเส้นให้ยาวขึ้น มือซ้ายรักษาการ์ดระหว่างออกหมัด

เฟรม 01 และ 16 ใช้รูปร่าง idle จาก avatar เดิมทุกชิ้นเพื่อกลับเข้าการเคลื่อนไหวปกติ กลุ่ม SVG ใช้ `data-part="torso|guard-arm|strike-arm|head"` และกำปั้นมี `data-part="guard-fist|strike-fist"` รากไหล่อยู่ใต้ศีรษะตามมุมกล้อง ข้อมือและกำปั้นแสดงผ่าน silhouette ด้านนอก ไม่มีเอฟเฟกต์มาบังท่า

## ข้อตกลงพิกัด — อย่าย่อหัวเพราะ padding

- พิกัดอ้างอิงตัวเดิม `0 0 64 64`, จุดตัวละคร `(32,32)`, หน้าไปทาง `(0,-1)`
- viewBox ใหม่ `-16 -32 96 112` เป็นพื้นที่โปร่งใสเผื่อแขน ไม่ใช่การขยายตัวละครหรือ hitbox
- อัตราวาดเดิม `52/64 = 0.8125` world units ต่อหน่วย SVG
- หลัง translate ไป origin และ rotate ตาม heading ให้วาดภาพ padded ด้วย `drawImage(image, -39, -52, 78, 91)` ก่อนคูณ scale ของผู้เรียกตามเดิม
- **ห้าม** วาดทั้งภาพ 96 × 112 ลงกล่อง 52 × 52 เพราะจะทำให้หัวเล็กและสัดส่วนผิด ห้ามใช้ศูนย์กลางภาพ padded แทน anchor `(32,32)`
- Atlas ช่อง `i` เริ่มที่ `(i*96,0)` ขนาด `96×112`; anchor ภายในช่องเป็น `(48,64)` ก่อนแปลงกลับ world
- การย้ายลำตัวไม่เกิน 2 หน่วย SVG เป็นท่าทางภายใน sprite ไม่ย้าย `p.x`, `p.y` หรือเงาที่ physics origin
- มุมภาพ = `atan2(attackFacing.y, attackFacing.x) + PI/2` ระหว่างโจมตี เพื่อใช้ทิศที่ล็อกตั้งแต่เริ่ม และกลับไปใช้ heading ปกติหลังจบ
- เงาพื้น ป้ายชื่อ และวงสตั้นยังเป็นหน้าที่ renderer เดิม
- สีต้นแบบ `#36d9e5` เป็นสีผู้เล่นจริงของเกม แปลง palette ตาม `shade` เดิมใน `player-avatar.js`; ค่าใน `timing.json.palette` บอกสีที่ใช้ทั้งหมด โปรดแทนสี fill/stroke/stop-color ของ sprite เองเมื่อโหลดผ่าน `Image` อย่าอาศัย CSS ภายนอกไหลเข้า SVG image
- แต่ละไฟล์มี gradient ID เฉพาะเฟรม ถ้าจะฝังหลายสีใน DOM เดียวให้เติม color namespace และแก้ `url(#...)` ให้ตรงด้วย

## งานของ AI ตัวถัดไป: เชื่อม → ทดสอบ → รวม

1. อ่าน `AGENTS.md`, `docs/CI_TESTING.md`, `docs/MAP_SCALE_RULES.md` จาก main ล่าสุดก่อนดำเนินงาน อ่านไฟล์ส่งมอบนี้และเปิดตัวอย่างกับ storyboard เพื่อพิจารณาภาพจริง งานรอบนี้ยังไม่ได้ QA
2. เชื่อมลำดับ SVG ใน renderer กลาง `player-avatar.js` / `character-system.js` โดยเลือกเฟรมจาก `elapsedMs = (PartyCombatMotion.TOTAL - attackRemaining) * 1000` และช่วง `[startMs,endMs)` ใน JSON อ่านสถานะเกมเดิม อย่าเริ่ม timer แยกหรือคิด hit จาก animation ที่เล่น
3. ให้ลำดับ draw ของแขนแทน pose `attack` เดิมและเส้นของ `PartyCombatMotion.drawAttack` อย่างครบถ้วน มิฉะนั้นจะยังมีเส้นยื่นจากหน้าและอาจกลายเป็นแขนซ้ำ ระวังผู้เรียกที่เรียก `PartyPlayerAvatar.draw` และ `drawAttack` โดยตรงนอก `PartyCharacters.draw`
4. คง `startAttack`, `stepAttack`, `hitPlayers`, เวลาสตั้น, คูลดาวน์, การหยุดเคลื่อนที่, attack cancellation, collision และ world scale เดิม ท่าต้องถูกยกเลิกเมื่อ stun / ถูกแปลงเป็นผี เช่นเดียวกับระบบเดิม อย่าให้แต่ละเฟรมสร้าง hit ซ้ำ
5. รักษา loading/error Canvas fallback ให้ใช้รูปร่างเดียวกับ SVG และเตรียม cache ตามสี/เฟรมล่วงหน้า ไม่ parse SVG หรือสร้าง `Image` ใหม่ทุก render ท่า hold/walk/portrait และมินิเกมที่ไม่ใช้หมัดไม่ควรเปลี่ยน
6. `COUNTDOWN DROP` มี `drawFist` และเวลาโจมตีของตัวเอง (`.12/.10/.18`) ให้แยกตัดสินใจว่าจะ map phase เข้าชุดนี้อย่างไร ห้ามแทนเวลามันด้วย 480 ms หรือเปลี่ยน stun ของเกมนั้นเพียงเพื่อให้ภาพตรง
7. ทดสอบไฟล์ SVG, ช่วงเฟรมโดยเฉพาะ 180/280/480 ms, สีผู้เล่นทั้งหมด, ทิศรอบตัว, fallback, การยกเลิกหมัด และการไม่ซ้อนเอฟเฟกต์เก่า ทดสอบใน Chromium/WebKit และขนาดใช้งานจริง รวมถึง mobile/iPad, local rendering, scale ของแต่ละเกม, carry/hold state, shadow/name และการไม่ตัดปลายหมัด
8. ใช้ชุดทดสอบที่เกี่ยวข้องตามผลกระทบ: `tests/avatar-topdown.cjs`, `tests/avatar-browser.cjs`, `tests/combat-motion.cjs`, `tests/character-system.cjs`, smoke, map-scale regression, affected minigame tests และ CI policy ล่าสุด หลังเชื่อม shared renderer อาจเข้าข่าย full QA ตาม repository policy
9. อัปเดต `docs/MAP_SCALE_AUDIT.md` ด้วยขนาดจริงและผลที่วัดได้เมื่อเชื่อม ห้ามขยาย hitbox ตาม padding; เปิด PR ตาม workflow, แก้ผลทดสอบที่ล้มเหลว และ **รวมเมื่อ checks ที่จำเป็นของ latest head ผ่านทั้งหมดเท่านั้น**

**โปรดรับหน้าที่ทดสอบและรวมต่อ ไม่ต้องตีความไฟล์ SVG หรือตัวอย่างนี้ว่าเกมได้แก้ไขหรือทดสอบแล้ว**

## ทำไมรอบนี้ไม่มี PR

workflow ของ repository เรียก QA อัตโนมัติเมื่อเปิด PR แต่ผู้ใช้ห้าม QA/ทดสอบในรอบออกแบบนี้ จึงส่งเป็น asset branch และไฟล์ตัวอย่างให้ AI ตัวถัดไปเปิด PR และทดสอบหลังเชื่อมงาน ไม่ได้แก้ CI, ใส่ skip-ci หรือปิด required checks
