## ภาพและสี

- ด้านหน้า: ผ้าขาวโค้งบนศีรษะ ชายผ้าพาดข้างแก้มสองข้าง ขอบผ้าพับ และเชือกสองวงที่มีร่องเกลียว
- ด้านบน: วาดเป็นทรงมงกุฎผ้ารูปวงรีแยกจากด้านหน้า เชือกเป็นวงที่มีความหนา ผ้าคลุมอยู่ด้านหลังแนวดวงตา หันไปทาง −Y ตามตัวละครมาตรฐาน ตัวอย่างด้านขวาใน `preview.svg` หมุน 90° ให้ตรงทิศของภาพ 2078
- ส่วนสีแดงด้านข้างในภาพ 2078 เป็นแขนของตัวละคร จึงไม่เพิ่มแขนหรือหางสีแดงเข้าใน overlay หมวก
- ไม่ฝังกรอบทอง พื้นม่วง หรือพื้นสนามจากภาพอ้างอิงลงในเครื่องแต่งกาย
- ผ้าขาวและเงาผ้าใช้สีเทากลางแบบตายตัว เชือกทั้งสองวงใช้ `fill="currentColor"` พร้อมเงาดำและไฮไลต์ขาวโปร่งใส เงาเหล่านี้ไม่ตรึงเชือกไว้เป็นสีแดง
- เปลี่ยนเฉพาะ attribute **`color` บน root `<svg>`** ให้ตรง `player.color` เช่น `color="#36d9e5"` ก่อนสร้าง `Image` หรือ serialize เป็น data/blob URL การเปลี่ยน CSS ของ `<img>` ภายนอกไม่ไหลเข้าภาพ SVG และไม่ใช่วิธีผูกสีของชุดนี้
- การใส่หมวกไม่เปลี่ยนสีตัวละคร เมื่อผู้เล่นเปลี่ยนสี เชือกต้องเปลี่ยนตามทันที ผ้ายังคงขาว ปลายสาย/รอยเงาไม่มีสีแดงฝังอยู่
- 12 สีที่เตรียมไว้เป็น palette ปัจจุบันใน `src/app/core/runtime.js` สีเก่าหรือสีใหม่ยังใช้ template + root color เดียวกันได้
- แยกชิ้นด้วย `data-part`: `cloth`, `cloth-left`, `cloth-right`, `cloth-crown`, `cloth-folded-edge`, `cloth-left-temple`, `cloth-right-temple`, `rope`, `rope-upper`, `rope-lower` ตามมุมที่มีชิ้นนั้น

## พิกัดและการวางซ้อน

### Portrait

`viewBox="0 0 96 96"`, anchor `(48,48)` ใช้กรอบเดียวกับ `PartyPlayerAvatar.svgForFront` และ `drawFront` วางหมวกหลังวาดหัว/ตาของตัวละครในพิกัดเดียวกัน ชายผ้าเป็นส่วนที่อยู่หน้าขอบแก้ม แต่ช่องหน้ากลางเปิดไว้ให้ดวงตาเดิม ไม่ย่อหรือย้ายตัวละครเพื่อใส่หมวก

### Overhead

`viewBox="0 0 64 64"`, anchor `(32,32)`, head pivot `(32,30)`, forward `(0,-1)` อัตราวาดเดิม `52/64` ดังนั้น overlay ใช้ rect `(-26,-26,52,52)` หลัง translate ไป origin และ rotate ตาม heading ของตัวละคร

ไม่ต้องใช้ padding ของ punch atlas เป็นขนาดหมวก พื้นที่หมวกนี้อยู่ในกรอบ 64 × 64; อย่าขยาย collision radius, world bounds, physics hitbox หรือพื้นที่ปฏิสัมพันธ์ตาม silhouette หมวก รักษา scale ของแต่ละ renderer และ 960 × 540 Host viewport ตามเดิม

ระหว่างต่อย ให้หมวกติดตาม **head transform** ของเฟรมหมัด ไม่หมุนตาม torso twist ทั้งก้อน และใช้ attackFacing เดียวกับหัวในเฟรมนั้น ดู `assets/animations/punch-v2/timing.json`: ศีรษะของเฟรมกลางใช้ `translate(torsoDx*.55, torsoDy*.55) rotate(headRotationDeg 32 30)`; เฟรมพักไม่มี offset อย่าให้หมวกค้างที่ตำแหน่ง idle ระหว่างหัวขยับ

ใช้หมวกหลังชั้นหัว แต่ก่อนชื่อ/วงสตั้น/สถานะที่ควรอยู่ด้านหน้า ห้ามใส่ตัวละครหรือเงาพื้นซ้ำจากตัวอย่าง `examples/` หากฝังหลายสี/หลายชุดใน DOM เดียว ให้ namespace gradient และ clipPath ID รวมถึง `url(#...)` ให้ไม่ชนกัน ไฟล์สีสำเร็จรูปแต่ละสีมี ID แยกไว้แล้ว

## พฤติกรรมที่ผู้ใช้ขอ — ให้ AI ตัวถัดไปเชื่อม

1. ผู้เล่นเดินเข้าโซน **`wardrobe`** ที่มีอยู่แล้วใน Party Plaza ใช้ `zoneAt` / `inZone` และพิกัดจาก `src/lobby/lobby-zones.json` ไม่สร้างเขตใหม่หรือเปลี่ยนขนาดร้าน
2. กด **B / `input.alt`** หนึ่งครั้งให้วน `none → white-rope-wrap → pirate-hat → none` ตามภาพ `wardrobe-cycle.svg` และ `../wardrobe-assets.json` หากมีรายการหมวกอื่นบน main ล่าสุด ให้รวมเข้าในรายการวนเดียวกันและคงตัวเลือกไม่ใส่หมวก
3. ใช้ขอบขาขึ้นของปุ่ม: ต้องปล่อยแล้วกดใหม่จึงเปลี่ยนอีกครั้ง กดค้างไม่วนทุกเฟรม และการกดค้างจากนอกเขตแล้วเดินเข้าเขตไม่ควรนับเป็นการกดใหม่
4. นอกโซนเสื้อผ้า คงหน้าที่ B เดิม ในโซนนี้ต้องไม่เรียก cancel/ปิดเมนูซ้อนกับการเปลี่ยนหมวก ไม่เปลี่ยน B ของมินิเกมหรือ BOARD
5. แสดงข้อความ **“B เปลี่ยนหมวก”** เมื่ออยู่ในเขตเสื้อผ้า การเดินออกจากเขตคงหมวกที่เลือกไว้ ไม่ถอดอัตโนมัติ
6. ผูกหมวกกับผู้เล่นรายนั้น เช่น `hatId: 'none' | 'white-rope-wrap' | 'pirate-hat'` ใช้ข้อมูล cosmetic ที่มีอยู่แล้วหาก main ล่าสุดเพิ่มไว้ ไม่เก็บเป็นตัวเลือก global ที่เปลี่ยนหมวกทุกคน
7. ใช้การ sync / reconnect / room snapshot เดิมส่งข้อมูลหมวก และรักษาการเลือกข้ามการออกจากเขต/เริ่มรอบตามโครงสร้างตัวตนของเกม สีเชือกต้องอ่านจากสีปัจจุบันของผู้เล่น ไม่เก็บสีเชือกแยกจนล้าหลัง

## จุดเชื่อมที่พบจากการอ่าน source

- `src/lobby/party-plaza.js`: B มี latch `plazaBPressed` อยู่แล้ว แต่เรียก `callbacks.cancel?.(p)` เสมอ ให้จัดการเฉพาะผู้เล่นที่อยู่ `wardrobe` แทน cancel แล้วคงเส้นทางเดิมในเขตอื่น
- `src/app/main.js`: `case 'wardrobe'` ของ A ยังแสดง “WARDROBE ยังไม่เปิดให้แต่งตัว”; `cancel(p)` ปิด plaza picker ให้ปรับตาม B ที่ผู้ใช้ขอ ไม่อ้างว่า A เป็นปุ่มเปลี่ยนหมวก
- `src/lobby/lobby-zones.json`: metadata ของ wardrobe ยังเป็น `trigger: button_A`; ปรับป้าย/metadata เฉพาะส่วนนี้ให้สอดคล้องกับการกด B หลังเชื่อม โดยคงเกมอาเขต/ready/เขตอื่นไว้
- `src/lobby/party-plaza.js` ใน `paint()`: `state` ที่ส่งเข้า avatar ยังไม่ส่งข้อมูลหมวก จึงต้องส่ง cosmetic selection ไปด้วย มิฉะนั้นแม้เปลี่ยน state สำเร็จก็จะไม่เห็นใน Plaza
- `player-avatar.js`: `costumeFor()` ยังคืน `standard` และไม่อ่าน legacy costume; ใส่การรองรับหมวกแบบ allowlist ชัดเจน อย่าทำให้ค่า costume เก่าที่ไม่รองรับสร้างของตกแต่งที่ไม่ได้ขอ
- `player-avatar.js`: cache เดิมผูกสี/pose เป็นหลัก เมื่อเชื่อมหมวกให้ key ครอบคลุม `color + hatId + projection + pose/frame` หรือทำ cache overlay แยกตาม `color + hatId + projection` โดยไม่สร้าง/parse SVG ทุก render
- เพิ่ม overlay ให้ทั้ง portrait, overhead และ loading/error fallback ที่มีอยู่ ระวัง path ของ punch atlas ที่วาดแยกจาก idle/walk/hold; หมวกต้องอยู่กับหัวจริงตลอดท่า
- `tests/avatar-topdown.cjs` มีข้อตกลงเดิมว่า costume เป็น standard อย่างเดียว อย่าลบข้อป้องกันทั้งหมด ให้ AI ที่ทดสอบปรับข้อกำหนดเฉพาะหมวกใหม่นี้ และรักษาตัวละครมาตรฐาน/legacy ที่ไม่รองรับให้เหมือนเดิม
- โปรดอ่าน owner instructions ของ core/bundles/peer compatibility และ build assets จาก main ล่าสุดก่อนแก้ เพราะ `app.js` / `app-controller.js` เป็นผลรวมของ source เดิม

## งานทดสอบและรวมของ AI ตัวถัดไป

อ่าน `AGENTS.md`, `docs/CI_TESTING.md`, `docs/MAP_SCALE_RULES.md` และกฎ connection ที่เกี่ยวข้องก่อนเชื่อม จากนั้นตรวจภาพทั้งสองมุม ขนาดใช้งานจริง/มือถือ/iPad ทุกสี ทุกทิศ idle/walk/hold/punch, loading/error fallback, การถอด/ใส่โดยไม่เปลี่ยนรูปทรงตัวเดิม, sync ระหว่างผู้เล่น, reconnect และ B ทั้งใน/นอกโซนโดยไม่กดซ้ำตอนค้าง รวมถึงข้อความ controller และลำดับการวาด
